Как запускать тесты

Unit/integration suite для dual-track сервиса: preprocess, FE/CPI second_, parity preds до 2 знаков vs df_for_service_*. Нет файла артефакта → fail, не skip. архитектура · контракт API · карта функций

предусловия эталоны prod синтетика модули каталог тестов env_template

Предусловия venv

  1. outboxml установлен через pip:
    pip install outboxml
    Shim mldataworker → outboxml из site-packages.
  2. Артефакты в каталоге results (см. ниже).

Эталонные датафреймы parity

ФайлСлотСодержимое
df_for_service_main.parquet main_ (legacy) вектор + preds_cf / preds_rg
df_for_service_second.parquet second_ (2.0.0) вектор + preds_cf / preds_rg

preds_* = ответ сервиса

  • preds_cf → classification_proba
  • preds_rg → regression_predictions (после маски IS_LAWYER)
  • сверка до 2 знаков после запятой

second_ — калибраторы

В эталоне second_ preds должны быть после CF/RG калибраторов (как score_second), иначе parity не сойдётся.

Опционально колонка split ∈ {train, test}. Лимит строк: INTEGRATION_TEST_MAX_ROWS.

Prod (рекомендуется) example_final

  1. Прогнать notebooks/example_final.ipynb до конца (export + save_df_for_service(..., slot="second", calibrators, threshold)).
  2. В integration/results/ должны быть:
    • UU_querulus_….pickle, cf_calibrator.pickle, rg_calibrator.pickle
    • df_for_service_second.parquet (с колонкой THRESHOLD)
  3. Для main_ (legacy): querulus_ansamble_legacy.pickle + df_for_service_main.parquet с preds того же пути, что main_predict.

Запуск (prod results)

cd ~/…/querulus # по умолчанию INTEGRATION_TEST_RESULTS_DIR = integration/results python -m unittest discover -s integration/tests -p "test_*.py" -v

Только parity

python -m unittest integration.tests.test_parity -v

Синтетика smoke

Локальный прогон без prod-моделей. Пишет integration/results/test_synth/.

python scripts/build_integration_test_artifacts.py # Linux / macOS INTEGRATION_TEST_RESULTS_DIR=integration/results/test_synth \ python -m unittest discover -s integration/tests -p "test_*.py" -v # PowerShell $env:INTEGRATION_TEST_RESULTS_DIR = "integration/results/test_synth" python -m unittest discover -s integration/tests -p "test_*.py" -v
Из каталога integration/
cd integration PYTHONPATH=.. python -m unittest discover -s tests -p "test_*.py" -v

Какие тесты за что

МодульНазначениеНужны артефакты
test_common_preprocess NaN, UPPER, даты, IS_LAWYER-маска (main ∩ second) нет (нужен outboxml)
test_second_features CPI, FE_*, THRESHOLD из вектора, калибраторы cal — частично
test_parity сервис vs df_for_service_{main,second} до 2 знаков; dual predict да

Полный список методов — test_catalog.html.

Переменные окружения

Шаблон: examples/querulus/env_template (скопировать в .env в корне querulus). Отдельного .env.example нет — единый файл для пайплайна, сервиса и тестов. Секция Integration tests — переменные INTEGRATION_TEST_*.

ПеременнаяСмысл
INTEGRATION_TEST_RESULTS_DIR каталог pickle/df (default integration/results)
INTEGRATION_TEST_DF_MAIN / INTEGRATION_TEST_DF_SECOND явные пути к df_for_service_*.parquet
INTEGRATION_TEST_MAIN_STEM / INTEGRATION_TEST_SECOND_STEM stem pickle без .pickle
INTEGRATION_TEST_MAIN_PICKLE / _SECOND_PICKLE явные пути к pickle (опционально)
INTEGRATION_TEST_METADATA / _CF_CAL / _RG_CAL meta и калибраторы second_
INTEGRATION_TEST_MAX_ROWS лимит строк на split (или на весь df)

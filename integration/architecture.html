Querulus · API 1.4.0

Архитектура HTTP-сервиса скоринга

Один запрос POST /api/predict гоняет две модели параллельно: боевой legacy в main_ и новый ансамбль 2.0.0 в second_. Ответ ОИСУУ всегда берётся из main_. Карта вызовов: functions.html. Контракт: contract.html. Тесты: tests.html.

Поток запроса runtime

Вход
POST /api/predict
Тело: main_model, main_request, опционально second_model + second_request (сырой вектор без FE_*).
▼ dual-track
main_ — legacy ансамбль
  1. 01
    Загрузка pickle results/{main_model}.pickle → [CF, RG]
  2. 02
    Предобработка "" → NaN, UPPER, EVENT_YEAR / APPLY_DELAY, валидация дат
  3. 03
    prepare_dataset + predict фиксированные списки CLASSIFICATION / REGRESSION_FEATURES
  4. 04
    Порог + маска IS_LAWYER THRESHOLD из вектора или 0.6; класс 1 или юрист → RG, иначе 0
  5. 05
    Ответ ОИСУУ oisuu_responce + main_response (+ SHAP в CPMComment)
second_ — модель 2.0.0
  1. 01
    Загрузка артефактов UU_querulus_….pickle + metadata + cf/rg_calibrator
  2. 02
    UPPER + даты + формы scoring/second.py · preprocess_second_vector
  3. 03
    FE_* в сервисе CPI REAL_2022, SHARE_WORK tier, ratio/diff/days/power
  4. 04
    predict → калибраторы CF proba cal, RG severity cal; clip из feature.clip в pickle
  5. 05
    τ из meta + IS_LAWYER best_threshold на cal-шкале; та же маска, что у main_
▼
Выход
Три блока JSON
oisuu_responce — контракт ОИСУУ (всегда от main_); main_response — полный результат legacy; second_response — результат 2.0.0 или {}, если second_* не переданы.

Пакеты кода integration/

service/

  • main.py — FastAPI, health/predict, скоринг main_
  • masking.py — общая маска IS_LAWYER
  • mldataworker_shim.py — alias на outboxml локально

features/

  • cpi.py — дефляция в рубли 2022
  • derived.py — FE_* из сырого second_request

scoring/

  • second.py — полный пайплайн second_
  • profiles.py — пути к pickle / meta / калибраторам

Корень: main.py (Docker entry), config.py, Dockerfile / compose / gitlab-ci / requirements. Точка локального запуска: python -m integration.

Артефакты на диске results/

main_

  • {legacy_stem}.pickle — [классификация, регрессия]

second_

  • UU_querulus_2026_10_09_16_51_20.pickle
  • metadata.json — best_threshold, threshold_scale: calibrated
  • cf_calibrator.pickle, rg_calibrator.pickle
Важно. В second_request нет готовых FE_* — их считает сервис. Отдельный dq_bounds.json не используется: клип числовых фич уже в feature.clip внутри model_config pickle (prepare_dataset). Порог second_ переотбирается в example_final после калибровки CF/RG. CPI: features/cpi_levels.json (уезжает в образ вместе с COPY features/).

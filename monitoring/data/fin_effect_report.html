2. Схема для бизнеса

Как читается финансовый эффект

Сравниваем два случайных потока убытков внутри филиала: model (модель работала) и control (модель не работала).

Control

Обычный процесс урегулирования без рекомендаций модели, с применением действующих бизнес-правил (в т.ч. доплата из лимита директора филиала, ЕМР +20% и пр.). Считаем средний расход на один инцидент (см. определение ниже).

−

Model

Тот же тип убытков, но с назначением в модель (РезультатПроверки ∈ {0,1}). В среднее входят и случаи, где рекомендацию не выполнили (ITT).

Средний расход на один инцидент

  • Единица — инцидент после дедупа по номеру убытка и схлопывания убытков: форма денежная / ремонт / соглашение; статус «первичный»; автотранспорт; пилотные филиалы без Марийского и Архангельского. Списанные по форме возмещения в схлопывание не входят.
  • Result: если у части убытков инцидента Result пустой, а у одного −100 (или 0/1) — на весь инцидент берём это значение.
  • Yfact = сумма СуммаПлатежа по убыткам инцидента (касса на дату отчёта). Observed ПСР вычитается из хвоста, не наращивает Yfact.
  • observed_PSR на инциденте = сумма выплат по претензии / ФУ / суду по схлопнутым убыткам.
  • Y365 = Yfact + NPV(ожидаемый ещё несозревший хвост ПСР по ретро-коэффициентам).

Формула эффекта

effect(H) = Σf wf · (ȲH(control, f) − ȲH(model, f))
wf = Nf / Σg Ng, Nf = число eligible-инцидентов филиала f (control + model)
Плюс = control дороже model = экономия. H ∈ {fact, 365}. Непростая разность глобальных средних: стратификация по филиалу сохраняет дизайн рандомизации.

Число инцидентов — сумма Nf по пилотным филиалам (в отчёте control / model отдельно). Марийский и Архангельский в ITT не входят (там модель ~100%, нет честного control).

ITT (intention-to-treat)

Главный результат — эффект назначения в model-поток, а не «эффект идеального исполнения». В model остаются и complied, и not_complied; соглашения / non-compliance строки не выкидывают (это post-treatment). Сценарий «если бы всегда исполняли» — отдельно (compliance B), это уже не ITT.

Шаг 1

Кого сравниваем

Model и control в пилотных филиалах. Соглашения и исполнение рекомендаций не выкидывают строки из ITT.

Шаг 2

Что уже заплатили

Yfact = сумма СуммаПлатежа по убыткам инцидента.

Шаг 3

Что ещё может прийти

Хвост ПСР по ретро (p_U, k_U, m_U, e_U). После соглашения — 7%.

Шаг 4

Два горизонта

Yfact — сейчас; Y365 — хвост с NPV на 1 год.

Шаг 5

Неопределённость

95% CI. Если интервал через 0 — эффект статистически не подтверждён.

Шаг 6

На год и сеть

Эффект/убыток × годовой поток пилота × множитель сети — сценарий.

3. Контракт данных и выборка

Единица: инцидент после дедупликации по номеру убытка и схлопывания убытков (числа — сумма, текст — мода). Списанные по форме возмещения в схлопывание не входят. Если у убытков инцидента Result=Null, а у одного −100 (или 0/1) — на весь инцидент берём это значение.

ITT: model = РезультатПроверки ∈ {0,1}; control = РезультатПроверки = −100. Соглашение и исполнение рекомендации не фильтруют ITT-популяцию, потому что это post-treatment.

Базовые фильтры: пилотные филиалы без Архангельского/Марийского; форма возмещения содержит «денежная», «ремонт» или «соглашение»; первичный убыток; объект «автотранспорт».

6. Yfact и Y365

Построение исхода каждого убытка i
paid_to_datei = numeric(СуммаПлатежаi, missing=0)
basei = kU,pilot×ODi, если OD>0; иначе mU,pilot
expected_open_PSRi = pU,pilot×(basei + eU,pilot)
observed_PSRi = претензияi + ФУi + судi
remainingi = max(qi×expected_open_PSRi − observed_PSRi, 0)
remaining_daysi = max(365 − agei, 0)
midpoint_daysi = remaining_daysi / 2
Yfacti = paid_to_datei
Y365i = paid_to_datei + remainingi / (1+r)midpoint_daysi/365
OD = СуммаОсновногоДолгаЗаявлено; q=1 без соглашения и q=7% при соглашении; r=12%; age=(t_calc−t0) в днях. Горизонт расчёта — только 365 дней.

Что означают remaining и midpoint

remaining — ещё не проявившийся хвост ПСР (номинал). Это не дисконт, а «сколько ещё может прийти» после вычитания уже видимых претензии/ФУ/суда.

midpoint — упрощение срока будущего платежа: хвост считается поступившим в середине оставшегося окна до горизонта 365 дней. Дисконтирование здесь — NPV (приведение будущих рублей к сегодняшним), а не рост ПСР со временем.

Числовые примеры remaining
Без соглашения: q=1, expected=100 000, observed=20 000 → remaining = max(100 000−20 000, 0) = 80 000
С соглашением: q=0.07, expected=100 000, observed=0 → remaining = max(7 000−0, 0) = 7 000
Уже «перебрали»: expected=100 000, observed=150 000 → remaining = 0
Пример midpoint / NPV для Y365
age=184, remaining=80 000, paid=50 000, r=12%
remaining_days=181, midpoint=90.5, DF≈1.028 → Y365 ≈ 50 000 + 77 821 = 127 821

11. Сезонный годовой эффект и сеть

Экстраполяция потока
sm,P = средняя доля месяца m в годовом pilot-потоке ретро
coveragem = доля дней месяца m, попавших в окно мониторинга
seasonal_exposure = Σm coveragem×sm,P
N_obs = число eligible-убытков current (model+control)
N_pilot_eligible_year = N_obs / seasonal_exposure
network_multiplier = 1 + volume_ratio_NP×risk_ratio_NP
annual_network_full = effect_per_case × N_pilot_eligible_year × network_multiplier
annual CI = [ci_low, ci_high] × N_pilot_eligible_year × network_multiplier
Горизонт Y365 не умножается на 365/30: масштабируется число новых убытков. CI годового эффекта — линейный перенос bootstrap CI с уровня убытка.

Зачем сезонность и откуда берутся числа

Нужно ответить: «в окне набралось N_obs убытков за неполный год; сколько ждать за полный типичный год?» Это число убытков, не сумма выплат.

  • sm — из ретро-пилота по дате (PAYMENT_ORDER_DATE_TIME / fallback), доля строк месяца в годе.
  • coveragem — по мониторингу ДатаЗаявления (_application_date): какая часть месяца попала в окно.
  • seasonal_exposure — какую долю типичного года мы уже увидели.
  • N_pilot_eligible_year — годовой поток eligible = N_obs / exposure.
  • risk_ratio — уже по деньгам TARGET_FREQ_AMOUNT (для сети).
Пример
N_obs = 2 500, seasonal_exposure = 0.25 → N_pilot_eligible_year = 2 500 / 0.25 = 10 000
effect_per_case = 4 694, network_multiplier = 2.5 → annual_network_full ≈ 4 694 × 10 000 × 2.5 = 117 350 000
Если окно попало в «лёгкие» месяцы, exposure меньше и годовой поток выше при том же N_obs — поэтому и нужна сезонная поправка.

12. Ограничения

  • ITT — эффект назначения в model-поток, включая фактический non-compliance.
  • Y365 — Yfact плюс модельный NPV остатка; это не полностью дозревший фактический горизонт.
  • Терминальные priors не содержат отдельного 365-таргета вызревания.
  • В мониторинге OD — СуммаОсновногоДолгаЗаявлено, а k_U калибруется на RECOVEREDMAINDEBT_LAST_INST_SUM.
  • 7% — экспертное допущение; midpoint — упрощение времени будущего хвоста.
  • Сетевой масштаб — сценарий, не рандомизированная оценка для nonpilot.
  • CI годового эффекта — линейный перенос CI с уровня убытка; отдельный bootstrap годового масштаба не считается.
